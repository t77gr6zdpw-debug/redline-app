# RedLine Studio × «Про Бізнес» — колаборація

Мобільно-орієнтований мікросайт-пропозиція для підписників Telegram-каналу
«Про Бізнес»: React 18 + Vite + Framer Motion, оптимізовано під Telegram
in-app browser.

## Розробка

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # продакшн-збірка у dist/
npm run preview  # локальний перегляд збірки
```

## Змінні оточення

Скопіюйте `.env.example` у `.env` і заповніть за потреби:

| Змінна | Призначення |
| --- | --- |
| `VITE_LEAD_ENDPOINT` | URL власної serverless-функції, яка приймає заявку (JSON) і пересилає її в Telegram Bot API / email / CRM. Токени бота зберігаються лише на сервері, не в клієнтському коді. Якщо не задано — форма показує чесне повідомлення та посилання на прямий контакт. |
| `VITE_TELEGRAM_CONTACT_URL` | Пряме посилання `https://t.me/...`, яке показується як запасний варіант, якщо відправка через `VITE_LEAD_ENDPOINT` недоступна або не налаштована. |
| `VITE_PROBIZNES_TELEGRAM_URL` | Посилання на канал «Про Бізнес», показується у футері. |

## Логотипи

`src/assets/logos/` містить надані оригінальні файли: `redline-wolf.png`
(вовк RedLine) і `probiznes-mark.jpeg` (монограма «Про Бізнес»). Обидва —
растрові рендери на чорному тлі; `Wordmark.jsx` виводить їх через
`mix-blend-mode: screen`, що математично прибирає чорний фон на будь-якій
темній підкладці без видимого прямокутника. Рекомендація на майбутнє:
стиснути `redline-wolf.png` (зараз ~1.7 МБ) через TinyPNG/Squoosh —
інструментів стиснення зображень у середовищі розробки не було, тож файл
лишився у вихідній якості.

## 3D-сцена в hero

Десктоп з `pointer: fine`, шириною ≥860px, увімкненим WebGL, без
`prefers-reduced-motion` і без ознак слабкого пристрою (`hardwareConcurrency`/
`deviceMemory`) отримує справжню 3D-сцену (`src/three/LogoScene3D.jsx`,
React Three Fiber + drei): обидва лого як текстуровані площини, що плавно
обертаються й «плавають» (`<Float>`), м'яке світіння через адитивний
sprite-німб, `<Sparkles>` частинки, туман, паралакс камери за курсором.
Рендер зупиняється (`frameloop="never"`), коли сцена йде за межі екрана.

Усі інші пристрої (мобільні, слабкі, touch-only, reduced-motion) отримують
легку CSS-версію (`CssLogoStage`) з тими самими логотипами й 3D-tilt через
`transform`, без WebGL. `ErrorBoundary` додатково гарантує відкат на
CSS-версію, якщо WebGL-сцена впаде в рантаймі. Це свідомий компроміс:
бриф вимагає і максимальної видовищності, і 60 FPS на Telegram in-app
browser — обидві вимоги виконані для відповідної аудиторії, а не принесені
в жертву одна одній.

## Аналітика

`src/lib/analytics.js` відправляє події в `window.gtag` або
`window.dataLayer` (GTM), якщо вони підключені на сторінці. Події:
`hero_cta_click`, `business_pass_flip`, `business_pass_activate`,
`comparison_interaction`, `form_open`, `form_submit_success`,
`telegram_click`.

## Валідація в цій сесії

У поточному середовищі доступ до `registry.npmjs.org` і `github.io`
заблокований мережевою політикою, тож ні `npm install`/`build`, ні візуальна
перевірка задеплоєного сайту (Playwright) звідси недоступні. Перевірено:

- статичний синтаксичний парс усіх `.jsx`-файлів (TypeScript-парсер,
  `--checkJs false --jsx react-jsx`) — 0 помилок;
- ESLint `no-undef`/`no-unused-vars` по всьому `src/` — 0 помилок;
- баланс дужок у всіх CSS-файлах;
- реальну збірку `npm install && npm run build` на GitHub Actions
  (`.github/workflows/deploy-pages.yml`) — це єдиний доступний спосіб
  перевірити, що нові залежності (`three`, `@react-three/fiber`,
  `@react-three/drei`) фактично встановлюються й збираються.

Що НЕ перевірено і потребує вашого візуального підтвердження (скриншот
або сама перевірка на телефоні/десктопі): чи справді рендериться 3D-сцена
без консольних помилок, чи не «стрибає» FPS, чи коректно виглядає
курсор/магнітні кнопки на різних пристроях. Надішліть скриншот або опис
проблеми — я оперативно поправлю.
